# 控车接口逆向指南（P5）

目标：找出 MG Live 的三个控车接口 —— **锁车 / 解锁 / 远程空调**。

---

## 为什么需要单独逆向

- MG Linker 的控车功能停在 **3.7 版**，之后的代码里已删除
- 车况接口（`getVehicleStatus`）是**只读**的，控车走的是**另一套接口**
- 控车指令通常需要：`user_id` + `user_name` + **指令签名**

---

## 抓包步骤

### 1. 准备

Stream 保持抓包开启。**先记下操作前的时间点**，方便定位。

### 2. 依次操作三次，每次之间停顿 5 秒

在 MG Live 里依次点击（**只点一次，等它执行完再点下一个**）：

| 顺序 | 操作 | 记录 |
|---|---|---|
| 1 | 点「解锁」 | 时间：____ |
| 2 | 点「锁车」 | 时间：____ |
| 3 | 点「开启空调」 | 时间：____ |

> 如果空调需要设置温度/时长，就按默认值直接确定。

### 3. 筛选请求

停止抓包，在记录里找**满足以下任一条件**的请求：

- 方法是 **POST**（控车多为 POST）
- URL 里含 `control` / `command` / `lock` / `climate` / `ac` / `veh` 字样
- 响应的 `msg` 是「指令下发成功」之类
- 时间点对上你上面记录的三个时间

### 4. 把找到的请求发我

每个操作一条，需要：

```
① 完整 URL
② 请求方法（GET/POST）
③ 请求头（全部，特别是 sign / token / userid）
④ 请求体（表单或 JSON 全文）
⑤ 响应内容
```

---

## 我这边要做的

1. 对比三次请求，找出**变化的字段**（就是指令本身）
2. 判断签名算法：
   - 如果 `sign` 每次都变 → 可能是 `MD5(参数 + 密钥)`，需要从 App 二进制里抠密钥
   - 如果 sign 不变 → 直接重放即可
3. 在 `SAICService.sendCommand` 里实现
4. 测试：先测只读的「查询指令状态」，确认通了再测真控车

---

## 风险提示

- **控车接口通常有更严的风控** —— 可能绑定设备指纹、要求更高权限
- 如果 sign 用 App 内密钥算，需要：
  - 越狱环境下 dump MG Live 的可执行文件
  - 用 IDA/Ghidra 找签名函数
  - 或者直接在越狱插件里 hook 它的签名函数为我们所用（**推荐，最省事**）

---

## 备选方案（如果接口逆向太难）

**直接 hook MG Live 自己**：
- 用 Theos 写插件，hook MG Live 的控车方法
- 我们 App 通过 XPC / 通知触发它执行
- 优点：不用管签名，App 自己算
- 缺点：需要 MG Live 在后台运行

这个方案和 MGHelper 是同一套技术，实现成本可控。
